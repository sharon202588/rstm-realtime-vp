# 氛围编程说明文档（优化终版）

Vibe Coding Guide for the Adaptive Real-Time Voice Virtual Patient System

## 0. 文档目的（请先读）

本说明文档用于指导前期测试（MVP / Pilot）阶段的开发与运行，目标是：

- **保证系统能跑、稳定、可解释**
- **固定核心机制，避免在工程阶段"悄然改研究"**
- **让 AI（Cursor / Codex）明确**：
  - 什么是世界设定
  - 什么是可实现逻辑
  - 什么是不能动的研究对象

**本文档优先级 高于任何临时代码注释或即兴 prompt。**

## 1. 项目一句话定位（不变）

本项目是一个**研究导向的实时语音虚拟患者系统**，
用于模拟医患沟通中**关系与情绪随沟通行为演化的过程**，
而非追求自由对话或语言智能最大化。

## 2. 系统的三大模块与职责分离（固定）

### 2.1 虚拟患者生成（实时语音模型）

**模型**：豆包端到端实时语音模型

**职责**：
- 生成虚拟患者的即时语音回应
- 保证低延迟、自然节奏、可打断

**明确不做**：
- ❌ 不评分
- ❌ 不判断好坏
- ❌ 不更新状态

它只负责"此刻患者怎么说话"。

### 2.2 评分判别器（CPAS Grader）

**模型**：doubao-seed-1-6-lite-251015（文字模型）

**职责**：
- 对医生上一轮完整发言进行结构化评分
- 输出 CPAS（SPIKES 阶段 + 安全门 + 双轨评分）

**输入**：
- 冻结的 grader_prompt.md
- 完整对话历史

**输出**：
- JSON only（用于计算，不用于生成）

它是"后台考官"，不参与对话。

### 2.3 关系状态轨迹模型（RSTM）

**性质**：确定性、规则驱动、非生成模型

**职责**：
- 将 CPAS 映射为连续关系状态
- 维护跨轮次的情绪惯性与关系记忆

**输出**：
- 连续状态 S(t)
- 映射到 7-level affective–interaction style

## 3. 前期测试阶段：参数直接固定（你要的关键结论）

✅ **前期测试（MVP / Pilot）统一采用以下参数**

### 3.1 关系累积参数（λ）

**λ = 0.8**

**含义（工程与教学共识）**：
- 表示关系具有显著惯性
- 单轮好或坏沟通不会立刻扭转关系
- 符合真实医患关系的"修复成本"

**为什么适合前期测试**：
- 不会出现剧烈振荡
- 高质量与低质量轨迹区分明显
- Mixed 情况下容易观察到"转折点"

### 3.2 情绪映射敏感度参数（c）

**c = 0.10**

**含义**：
- 控制 CCI_t → S(t) 的非线性斜率
- 决定情绪"硬不硬""快不快"

**为什么前期测试选 0.10**：
- 线性区间较宽
- 避免 1–2 轮评分直接饱和到 ±1
- 有利于观察渐进变化与平滑性

⚠️ **在前期测试阶段**：
- 不做 c 的 runtime 调整
- 不做自动调参

### 3.3 明确写进 spec 的状态更新公式

在前期测试中，统一采用：

```
CCI_t = λ · CCI_(t-1) + CPAS_t
S(t)  = tanh(c · CCI_t)
```

并满足：
- S(t) ∈ (-1, 1)

## 4. 一次完整对话轮次的运行逻辑（最终确认版）

以下是真实执行顺序，不是概念顺序。

### Phase A：实时语音回应（最高优先级）

1. 医生完成一轮发言（语音 / 文本）
2. 系统立即调用：
   - 当前 S(t) 对应的风格约束
   - 豆包实时语音模型
3. 虚拟患者立刻开始说话

**重要约束**：
- ❌ 不等待评分
- ❌ 不等待状态更新

这是为了保证心理真实性与对话流畅度。

### Phase B：后台评分（异步执行）

在患者语音已经开始或结束后：

1. 系统调用 CPAS Grader（lite 文本模型）
2. 使用冻结评分提示词
3. 输出 CPAS JSON

**该过程**：
- 对学习者不可见
- 对当前轮语音无影响

### Phase C：关系状态更新（确定性）

1. 读取当前 CCI_(t-1) 与 S(t)
2. 根据 CPAS 计算：
   - 新的 CCI_t
   - 新的 S(t)
3. 将 S(t) 存储为下一轮的初始状态

### Phase D：状态 → 风格映射（确定实时语音模型输出风格）

将更新后的 S(t) 映射到 7-level affective–interaction style

**用途**：
- 确定下一轮实时语音模型的输出风格
- 风格映射结果直接注入到豆包端到端实时语音模型的系统提示词中
- 约束虚拟患者的语音回应风格，确保与当前关系状态一致

**实现**：
- 7-level 风格映射器将连续状态 S(t) 映射到离散风格级别
- 生成风格约束提示词
- 该提示词用于控制实时语音模型的输出风格
